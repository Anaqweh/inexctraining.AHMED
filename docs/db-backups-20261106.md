# النسخ الاحتياطي اليومي لقاعدة البيانات — 2026-11-06

كل بيانات المنصة الحيّة (التسجيلات، المدفوعات، جهات الاتصال، الحملات، البطاقات) في PostgreSQL داخل حاوية `db` على خادم DigitalOcean — الواجهة وحدها هي المحفوظة في GitHub. سكربت `scripts/setup-db-backups.sh` يثبّت منظومة نسخ كاملة بأمر واحد.

## التثبيت (مرة واحدة، على الخادم)

```bash
curl -fsSL https://raw.githubusercontent.com/Anaqweh/inexctraining.AHMED/master/scripts/setup-db-backups.sh | sudo bash
```

يتحقق من البيئة (compose، خدمة db، ‏pg_dump)، يثبّت السكربتين في `/opt/inexc-training/backups/bin/`، يضيف cron يوميًا (02:17 بتوقيت الخادم)، **ويأخذ أول نسخة فورًا** ويطبع نتيجتها.

## ماذا يفعل يوميًا

- `pg_dump -Fc` (مضغوطة، تدعم الاستعادة الانتقائية) ببيانات اعتماد حاوية db نفسها — لا أسرار في السكربت أو cron.
- حراسات قبل الاعتماد: حجم ≥ 20KB + قراءة فهرس `pg_restore --list` كاملًا + بصمة sha256.
- تدوير: 30 نسخة يومية، ونسخة الأحد تُرقّى أسبوعية (12 أسبوعًا) — عمق استرجاع ~3 أشهر.
- أي فشل: سطر `FAIL السبب` في `/opt/inexc-training/backups/last-status` وخروج غير صفري (يظهر في `backup.log` وبريد cron إن كان مهيأ) — ولا تُمسّ النسخ السابقة أبدًا.

## الاستعادة

```bash
sudo /opt/inexc-training/backups/bin/inexc-db-restore.sh /opt/inexc-training/backups/daily/<الملف>.dump --yes
```

يتحقق من sha256، يرفض ملفًا معدّلًا، يوقف `api` أثناء الاستعادة ثم يعيده. بدون `--yes` يعرض تحذيرًا فقط.

## نسخة خارج الخادم (موصى بها لاحقًا)

النسخ حاليًا على قرص الخادم نفسه؛ لحماية من فقدان الخادم بالكامل: ثبّت `rclone`، هيّئ وجهة (DigitalOcean Spaces مثلًا)، وضع اسمها سطرًا واحدًا في `/opt/inexc-training/backups/remote.conf` — سترفع كل نسخة تلقائيًا، وفشل الرفع يُعلّم النسخة FAIL.

## التحقق قبل الاعتماد

حُوكي السكربتان محليًا بمحاكي docker: نجاح أول تشغيل، تدوير 38←30 مع ملفات sha، ترقية الأحد الأسبوعية، فشل الحجم الصغير وفشل فهرس pg_restore (حالة FAIL وخروج 1 دون مساس بالنسخ القائمة)، ورفض الاستعادة بدون `--yes` أو لملف معدّل البصمة. فحص `bash -n` للثلاثة.
